# 灵魂文件随包发布，而不是指向外部路径

灵魂文件是主人持续打磨的私人设定，直觉上应该放在包外、由配置指向它。选择反过来：`FairySOUL.md` 打进发布产物，默认相对包根解析。

## Considered Options

- **默认指向用户全局路径**（如 `~/.dsh/FairySOUL.md`）：插件于是依赖每台机器的目录布局。搬运包或删除原目录就失效，且每个安装者都要自己放一份文件才有人格。
- **默认指向开发机的绝对路径**：最糟。别人装下来必然指向不存在的文件。

## Consequences

- 安装即用，无需任何配置；每个安装实例拿到同一份人格。
- 插件可以在任意位置运行，也能在开发目录被删除后继续工作。
- 代价：想换人格必须改包内文件或显式配置 `soulPath`。这是刻意的——默认行为要可预测，个性化要显式。
- 发布产物因此必须把 `FairySOUL.md` 列入 `files` 白名单。漏掉它不会报错，只会让所有人装到空人格，因此 `verify/install-check.mjs` 对此有专门断言。
